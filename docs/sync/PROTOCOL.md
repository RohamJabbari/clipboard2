# Clipboard2 Sync Protocol v1

The contract between the Mac app, the Windows app and `clipboard2-api`. Everything a user syncs is
encrypted on the device; the server stores ciphertext plus the metadata listed under
[What the server sees](#what-the-server-sees). Byte-exact behaviour is pinned by
[`test-vectors.json`](test-vectors.json) (generated by `server/scripts/vectors.ts`); both clients
must pass every vector.

Accounts live in `clipboard2-db` itself. No third-party auth, no emails. **The password never leaves
the device**, and there is **no password recovery**: a forgotten password means the synced data is
gone. Both apps say so at sign-up.

## Conventions

- **Bytes in JSON** are standard base64 with padding.
- **IDs** (`uid`, space, item and blob ids) are UUIDs in lowercase hyphenated form. Swift's `uuidString` is uppercase, so lowercase it before use.
- **Invite ids** are lowercase hex.
- **Times** are Unix milliseconds as JSON integers.
- **Strings** are UTF-8 everywhere.
- **Passwords** are Unicode-NFC-normalised before key derivation.
- **Emails** are trimmed and lowercased by the client before every use. The server does the same.
- **`‖`** means concatenation.

## Cryptography

### Primitives

| Name | Definition |
|---|---|
| `AEAD(key, plaintext, aad)` | AES-256-GCM with a random 12-byte nonce. Output `0x01 ‖ nonce(12) ‖ ciphertext ‖ tag(16)`. Decryption rejects any other version byte. |
| `HKDF(ikm, salt, info)` | HKDF-SHA256 with 32 bytes of output. An empty salt is zero-length: CryptoKit `Data()`, .NET `[]`. |
| `PBKDF2(password, salt, iterations)` | PBKDF2-HMAC-SHA256 over `NFC(password)` as UTF-8, 32-byte output. New accounts use **600 000** iterations and a random 16-byte salt. |
| P-256 public key | X9.63 uncompressed, 65 bytes: `0x04 ‖ X ‖ Y`. |
| P-256 private key | Raw scalar, 32 bytes (CryptoKit `rawRepresentation`, .NET `ECParameters.D`). |
| `ECDH(priv, pub)` | The raw 32-byte X coordinate of the shared point. |

### Password-derived keys

```
master   = PBKDF2(password, kdfSalt, iterations)
authKey  = HKDF(master, "", "clipboard2 auth")   sent to the server to log in, never stored by the client
wrapKey  = HKDF(master, "", "clipboard2 wrap")   never leaves the device
```

The server stores only `scrypt(authKey)`, so its database can't be used to derive `wrapKey`.

### Account and space keys

```
AK          = random(32)                                   account key, one per user
wrappedAK   = AEAD(wrapKey, AK, "c2/ak/v1/" + uid)
idPriv      = random P-256 key; idPub = its public key
wrappedPriv = AEAD(AK, idPriv, "c2/priv/v1/" + uid)

SK          = random(32)                                   one per space (personal and each group)
wrapSpaceKey(SK, spaceId, memberUid, memberPub):
    eph       = fresh P-256 key
    wk        = HKDF(ECDH(eph.priv, memberPub), eph.pub ‖ memberPub, "c2/space/v1/" + spaceId)
    wrapped   = eph.pub(65) ‖ AEAD(wk, SK, "c2/space/v1/" + spaceId + "/" + memberUid)
unwrap: split off the first 65 bytes as eph.pub, then wk = HKDF(ECDH(idPriv, eph.pub), eph.pub ‖ idPub, …)

itemKey     = HKDF(SK, "", "c2/item/v1")
nameKey     = HKDF(SK, "", "c2/name/v1")
item        = AEAD(itemKey, payloadJSON, "c2/item/v1/" + spaceId + "/" + itemId + "/" + category)
blob        = AEAD(itemKey, bytes,       "c2/blob/v1/" + spaceId + "/" + blobId)
groupName   = AEAD(nameKey, utf8(name),  "c2/name/v1/" + spaceId)
```

The client generates `uid` (a random UUID) at sign-up because it's part of the AAD.

### Invite codes

```
codeBytes = random(16)                                     128 bits
code      = base32(codeBytes)                              RFC 4648 alphabet A–Z 2–7, no padding: 26 characters,
                                                           shown as 4-character groups joined by "-"
                                                           (XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XX)
inviteId  = hex(SHA-256(codeBytes))                        64 lowercase hex chars; the server only ever sees this
inviteKey = HKDF(codeBytes, "", "clipboard2 invite")
sealedKey = AEAD(inviteKey, SK, "c2/invite/v1/" + spaceId)
```

**Parsing a typed code:**
1. Remove spaces and `-`, then uppercase.
2. Map `0`→`O`, `1`→`I` and `8`→`B`, to forgive misreadings.
3. Require exactly 26 characters and base32-decode them to 16 bytes. The last 2 bits must be zero.

### Sign-up codes

Sign-up is invite-only. A **sign-up code** is made by the server (`POST /v1/signup-codes`), not the
client, and isn't key material:

```
code       = 80 random bits in the invite-code alphabet: 16 characters,
             shown as 4 groups of 4 joined by "-" (XXXX-XXXX-XXXX-XXXX)
normalised = the typed code with spaces and "-" removed, uppercased, 0→O, 1→I, 8→B; exactly 16 characters
stored     = SHA-256(utf8(normalised))                     the server keeps only this
```

The app's "Invite code" field takes either kind: 16 characters after normalising is a sign-up code
(sent as typed, as `signupCode`), 26 is a group invite code (sent as `groupInviteId` = its `inviteId`,
and joined right after the account exists).

### Known v1 limits
- Removing a member doesn't rotate the space key. Their access ends because the server refuses them, not because of crypto.
- Emails are never verified. Someone can register an address they don't own, which only matters as a display name.

## Item payloads

The plaintext inside `item` is one compact JSON object. Readers ignore unknown fields; writers omit nulls.

```jsonc
// type "clip"
{"v":1,"type":"clip","kind":"text|richText|image|file","text":"…","preview":"…",
 "rtf":"<b64>","html":"<b64>","files":["file:///…"],"fileBlobs":[{"name":"Report.pdf","blob":"<blob uuid>","size":0}],
 "imageBlob":"<blob uuid>","thumbBlob":"<blob uuid>","imageWidth":0,"imageHeight":0,"byteCount":0,
 "sourceId":"com.apple.Safari","sourceName":"Safari",
 "isPinned":false,"pinnedAt":null,"label":null,"copyCount":1,
 "createdAt":0,"lastCopiedAt":0,"contentHash":"text:…"}
// type "snippet"
{"v":1,"type":"snippet","name":"…","keyword":"…","body":"…","createdAt":0,"updatedAt":0}
// type "secret"
{"v":1,"type":"secret","name":"…","value":"…","createdAt":0}
```

- **Images:** the PNG and its thumbnail are uploaded as two encrypted blobs. Their ids are listed in the payload and in `blobIds`.
- **Rich text that won't fit:** if `rtf` + `html` push the ciphertext past the item limit, drop them and sync the item as `text`.
- **Files:** each regular file (not folders) of up to 25 MiB sealed, at most 10 per item, is uploaded as an encrypted blob, like images. `fileBlobs` lists them in upload order (`name` is the last path component, `size` the plaintext bytes) and `blobIds` repeats their ids. Receivers save them as `Synced Files/<item id>/<name>` — after stripping any path from `name` — and keep the item a file clip pointing there, so pasting puts real files on the clipboard. Files without a blob (too large, folders, or from a sender without `fileBlobs`) arrive as their names, as text. Deleting the item deletes its folder.

| Category | Payload | `sortAt` |
|---|---|---|
| `history` | clip with `isPinned: false` | `lastCopiedAt` |
| `pinned` | clip with `isPinned: true` | `lastCopiedAt` |
| `snippet` | snippet | `updatedAt` |
| `secret` | secret | `createdAt` |

Pinning or unpinning changes the category, and the category is part of the AAD, so the client re-encrypts and `PUT`s again.

## API

- Bodies are JSON.
- Every route except `/v1/auth/prelogin`, `/v1/auth/signup` and `/v1/auth/login` needs `Authorization: Bearer <session token>`.

**Errors** are `{"error": "<code>", "message": "…"}`:

| Code | Status |
|---|---|
| `unauthenticated` | 401: missing, unknown, revoked or expired session |
| `invalid_credentials` | 401 |
| `forbidden` | 403 |
| `invite_required` | 403: sign-up without `signupCode` or `groupInviteId` |
| `invite_invalid` | 403: that sign-up code or group invite is unknown, used or expired |
| `not_found` | 404 |
| `no_account` | 404 |
| `conflict` | 409 |
| `username_taken` | 409 |
| `invalid` | 400 |
| `clock_skew` | 400: an item time is more than 10 minutes ahead of the server's clock |
| `too_large` | 413 |
| `quota_exceeded` | 403 for per-user and per-space limits; 413 with `"scope": "group"` or `"scope": "server"` for group and server storage (see [Limits](#limits)) |
| `rate_limited` | 429, with `Retry-After` in seconds and `retryAfter` in the body |
| `too_many_codes` | 429: already 10 open sign-up codes |

### Auth and sessions

| Request | Response |
|---|---|
| `POST /v1/auth/prelogin` `{email}` | `{kdf: {alg: "pbkdf2-sha256", salt, iterations}}`. Unknown emails get a deterministic fake salt (`HMAC-SHA256(serverKey, email)[0..16]`, 600 000 iterations), so this can't be used to find accounts. |
| `POST /v1/auth/signup` `{email, authKey, kdf: {salt, iterations}, uid, wrappedAccountKey, publicKey, wrappedPrivateKey, personalSpace: {id, wrappedKey}, deviceName?, username?, signupCode?, groupInviteId?}` | `201 Session`; `403 invite_required` without either invite, `403 invite_invalid` if it's unknown, used or expired; `409 conflict` if the email is taken, `409 username_taken` if the username is |
| `POST /v1/auth/login` `{email, authKey, deviceName?}` | `200 Session`; `401 invalid_credentials` |
| `POST /v1/auth/logout` | `204`, revokes the calling session |
| `PUT /v1/account/password` `{authKey, newAuthKey, kdf: {salt, iterations}, wrappedAccountKey}` | `204`. Checks the current `authKey`, replaces the password verifier and `wrappedAK` (AK itself doesn't change), and revokes every other session. |
| `GET /v1/account` | `Account` |
| `PUT /v1/account/username` `{username}` | `200 {username}`; `409 username_taken` |
| `DELETE /v1/account` `{authKey}` | `204`. Deletes sessions, sign-up codes, the personal space, owned groups (items, blobs, invites) and memberships. Every live item the user wrote in other people's groups becomes a `user` tombstone (its `updatedAt` raised to the deletion time, `authorUid` then `null`), and their blobs there are deleted. |
| `GET /v1/sessions` | `{sessions: [{id, deviceName, createdAt, lastUsedAt, current}]}`, the caller's unexpired sessions, most recently used first. `id` is a UUID; `current` marks the calling session. |
| `DELETE /v1/sessions/:id` | `204`, signs that device out (it may be the calling session); `404` if it isn't one of the caller's |
| `POST /v1/signup-codes` | `201 {id, code, expiresAt}`. A new [sign-up code](#sign-up-codes), valid 14 days, single use. `code` is shown only here. `429 too_many_codes` with 10 open (unused, unexpired) codes. |
| `GET /v1/signup-codes` | `{codes: [{id, createdAt, expiresAt}]}`, the caller's open codes |
| `DELETE /v1/signup-codes/:id` | `204`, revokes an open code; `404` otherwise |

```jsonc
Session = {"token","expiresAt","account": Account}
Account = {"uid","email","kdf":{"alg":"pbkdf2-sha256","salt","iterations"},
           "wrappedAccountKey","publicKey","wrappedPrivateKey","personalSpaceId",
           "username":null|"<string>"}
```

- **Tokens:** 32 random bytes as base64url. The server stores only their SHA-256.
- **Expiry:** sessions expire 30 days after their last use. Every authenticated request slides the expiry forward, at most once an hour.
- **On the device:** the token, uid, email, AK and idPriv go in the Keychain (Mac, service `<bundle id>.sync`) or Credential Manager (Windows, `Clipboard2/sync/*`), never in settings files.
- **Session ended:** on `401 unauthenticated` the client asks for the password again (prelogin, then login), unlocks AK from the fresh `Account`, and carries on.
- **Signup:** `kdf.iterations` must be at least 100 000.
- **Usernames:** optional; trimmed and NFC-normalized, then 3–24 Unicode letters, digits, `_`, `.` or `-`, starting with a letter or digit (`invalid` otherwise). Stored as typed, unique case-insensitively. Accounts without one have `username: null`.
- **Sign-up invites:** `signupCode` (as typed; the server normalises it) is consumed by the sign-up.
  `groupInviteId` must be an unused, unexpired group invite; sign-up doesn't consume it, joining does.
  The invite is checked before the email, so sign-up can't be used to find accounts without one.
  New servers get their first code from `npm run signup-code` (an operator code that belongs to nobody).
- **Rate limits:** prelogin, signup and login (and the password checks of password change and account
  deletion) share one limit per IP and one per email, counted in Postgres in fixed one-minute windows,
  so they hold across instances. The client IP is the last `X-Forwarded-For` hop (Cloud Run's front
  end); earlier entries are ignored. Password hashing runs at most 2 at a time per instance with a
  short queue; beyond it the answer is `429 rate_limited` with `retryAfter`.

### Spaces and groups

**Endpoints:**

| Request | Response |
|---|---|
| `GET /v1/spaces` | `{spaces: [Space]}`, every space the caller belongs to |
| `POST /v1/groups` `{id, encryptedName, wrappedKey}` | `201 Space`. The caller becomes owner; `wrappedKey` is SK wrapped to the caller. |
| `PATCH /v1/groups/:id` `{encryptedName}` | `204`, owner only |
| `DELETE /v1/groups/:id` | `204`, owner only. Removes all items, blobs and invites. |
| `GET /v1/groups/:id/members` | `{members: [{uid, username, name, role}]}`, members only, owner first. `username` may be `null`; `name` is as in `Space.members`. No emails. |
| `DELETE /v1/groups/:id/members/:uid` | `204`. The owner can remove others; a member can remove themselves (leave). The owner can't leave and has to delete the group instead. |

```jsonc
Space = {"id","kind":"personal|group","role":"owner|member","ownerUid",
         "wrappedKey","encryptedName":null|"<b64>","memberCount",
         "members":[{"uid","name"}],"createdAt"}
```

- **`members`:** everyone in the space, owner first (a personal space lists only the caller). `name` is the username, or the email's part before `@` if there is none. Clients show it next to items by matching `authorUid`.

### Invites

| Request | Response |
|---|---|
| `POST /v1/groups/:id/invites` `{inviteId, sealedKey}` | `201 {inviteId, expiresAt}`, owner only. Valid 7 days, single use. |
| `GET /v1/groups/:id/invites` | `{invites: [{inviteId, createdAt, expiresAt}]}`, owner only, pending invites only |
| `DELETE /v1/groups/:id/invites/:inviteId` | `204`, owner only, revokes the invite |
| `GET /v1/invites/:inviteId` | `{spaceId, sealedKey, encryptedName, memberCount, expiresAt}`, any signed-in user; `404` if unknown, used or expired |
| `POST /v1/invites/:inviteId/accept` `{wrappedKey}` | `201 Space`. Joins as `member` and consumes the invite. `wrappedKey` is SK wrapped to the caller's own public key. `409` if already a member. |

**Flow:**
1. **Owner:** generates a code, uploads `{inviteId, sealedKey}`, and shows the code once, with a Copy button.
2. **Invitee:** pastes the code, then `GET /v1/invites/:inviteId`, opens `sealedKey` to get SK, decrypts `encryptedName` to show "Join ‹name›?", and on confirm calls `accept` with SK wrapped to itself.

**Rate limits:** invite fetches and accepts have their own limit of 20/min per user.

### Items

**Endpoints:**

| Request | Response |
|---|---|
| `GET /v1/spaces/:id/changes?since=<seq>&limit=<≤500>` | `{items: [Item], nextSince, hasMore, resetRequired}` |
| `PUT /v1/spaces/:id/items/:itemId` `{category, sortAt, updatedAt, ciphertext, blobIds}` | `200 {seq, trimmed: [itemId]}` or `409 {error: "conflict", current: Item}` |
| `DELETE /v1/spaces/:id/items/:itemId?updatedAt=<ms>` | `200 {seq}`, idempotent. Writes a `user` tombstone and deletes the item's blobs. Returns `409 {current}` if the live item has a newer `updatedAt`. |

**Changes:** `nextSince` is the highest `seq` returned. `since=0` returns the full current state. Each item's `seq` is a server-global, strictly increasing number that is assigned again on every change.
- Within a space, `seq` order is commit order: every item write locks the space row before taking a `seq`, so a cursor never moves past a change that becomes visible later.
- The purge horizon and the page are read in one REPEATABLE READ snapshot.

**Upsert rule:** last write wins on `updatedAt`.
- The incoming version is kept when `incoming.updatedAt >= stored.updatedAt`.
- A `user` tombstone counts as a stored version.
- Every id in `blobIds` must be a blob already registered in the same space. `blobIds` holds at most 12 ids.

**Write checks** (`PUT` and `DELETE`):
- `sortAt` or `updatedAt` more than 10 minutes ahead of the server's clock → `400 clock_skew`.
- In a group, an existing item (tombstones included) may be overwritten or deleted only by its
  author (`authorUid`) or the group owner; anyone else gets `403 forbidden`. Creating new items is
  open to every member. Deleting an item that is already a `user` tombstone stays an idempotent `200`.
- The writer becomes the item's `authorUid`.

```jsonc
Item = {"id","category":"history|pinned|snippet|secret","seq","sortAt","updatedAt",
        "deleted":null|"user"|"trimmed","ciphertext":null|"<b64>","blobIds":[],"authorUid"}
```

**Retention:**
- `pinned`, `snippet` and `secret` items stay until deleted.
- After any `history` upsert, the server keeps the newest **200** `history` items in that space by `sortAt`, ties broken by `id`. All others become `trimmed` tombstones, their blobs are deleted, and the `PUT` response lists them.
- Tombstones are kept for **90 days**. A `since` older than the space's purge horizon returns `{resetRequired: true}`, and the client re-syncs from `since=0`.

### Blobs

| Request | Response |
|---|---|
| `POST /v1/spaces/:id/blobs` `{id, size, ifGenerationMatch?}` | `{url, method: "PUT", headers, expiresAt}`. Registers the blob and checks quota. Upload the ciphertext with exactly those headers; they include `x-goog-content-length-range`. |
| `GET /v1/spaces/:id/blobs/:blobId` | `{url, expiresAt}`, a signed GET valid for 15 minutes |

- The GCS object path is `<spaceId>/<blobId>`.
- **`ifGenerationMatch: true`** (current clients always send it): the signed PUT also requires `x-goog-if-generation-match: 0`, which is in `headers`, so the URL can create the object but never overwrite one.
- Asking again for your own pending blob (same size) returns a fresh URL. Once an item references the blob, no URL is issued again: `409 conflict`.
- A blob no item references 24 hours after registration may be garbage-collected.

### Limits

| Limit | Value | Error |
|---|---|---|
| Item ciphertext | 2 MB | `too_large` |
| Blob | 25 MB | `too_large` |
| Blob ids per item | 12 | `invalid` |
| Bytes per user (items + blobs they wrote) | 1 GB | 403 `quota_exceeded` |
| Non-history items per space | 5 000 | 403 `quota_exceeded` |
| Bytes per group (live items + blobs) | 2 GB | 413 `quota_exceeded`, `"scope": "group"` |
| Live items per group (history counted after trimming) | 5 000 | 413 `quota_exceeded`, `"scope": "group"` |
| Bytes on the server (`LIMIT_TOTAL_BYTES`) | 20 GB | 413 `quota_exceeded`, `"scope": "server"` |
| Groups owned | 20 | 403 `quota_exceeded` |
| Members per group | 50 | 403 `quota_exceeded` |
| Pending invites per group | 20 | 403 `quota_exceeded` |
| Open sign-up codes per user | 10 | `too_many_codes` |
| Requests | 120/min per user | `rate_limited` |
| Prelogin, signup and login | 20/min per IP; 10/min per email | `rate_limited` |
| Password hashing | 2 at a time per instance, short queue | `rate_limited` |

## What the server sees

**Visible to the server:**
- email and username
- the scrypt of `authKey`
- KDF salt and iterations
- session hashes, device names and last use
- group membership and roles
- invite ids and expiry
- sign-up code hashes, who made and used each, and expiry
- for about two minutes, auth attempt counts keyed by an HMAC of the IP or email
- per item: category, `sortAt`, `updatedAt`, size, author, blob ids and sizes

Request logs record method, URL and status only: no IPs or emails. Members see each other's
username or email local part (`name`), never the email.

**Never visible to the server:** the password, `wrapKey`, invite codes, item contents, group names, snippet and secret names and values, and every key except public keys.

## Client sync rules

1. **State.** A local *sync meta* table holds `(localId, spaceId, category, fingerprint, remoteSeq, updatedAt)`. `fingerprint` is the SHA-256 of the canonical payload JSON last sent or received. Each space also has a `since` cursor.
2. **Tick.** Triggered 3 s after a local store change (debounced), every 60 s, when the panel opens, and on "Sync now". One tick at a time.
   1. Call `GET /v1/spaces` and unwrap any new space keys.
   2. For each space, pull before pushing.
3. **Pull.** Page through `changes` and apply each item:
   - **Newer upsert:** decrypt. For a clip with images, download and decrypt the blobs and write them to the blob store **before** inserting or updating the item.
   - **`user` tombstone:** delete locally.
   - **`trimmed` tombstone:** in the personal space, stop tracking the item but keep the local copy. In a group, delete it locally.
   - Store the fingerprint and `remoteSeq`, then advance `since`.
4. **Push.** Compare the local items of each space against the meta table:
   - **New or changed fingerprint:** encrypt and `PUT`. Upload new blobs first.
   - **Meta without a local item:** `DELETE`.
   - **On `409`:** apply `current` the same way as a pull.
   - **Personal history:** push only the newest 200 by `lastCopiedAt`.
5. **Duplicates.** When two items in one space share a `contentHash`, the lexicographically smaller id wins. Merge `copyCount`, keep the larger `lastCopiedAt`, keep the label and pin of either, and delete the loser (which pushes a tombstone).
6. **Local scope.**
   - Dedupe, merge and "remove history copies of saved secrets" each run within one space only.
   - Groups locally keep the newest 200 history items per space.
   - The user's own retention setting applies only to the personal space.
7. **Log out** calls `/v1/auth/logout` and then deletes local group data, sync meta, cursors and stored keys. Personal local history stays.
8. **Share to group** copies the item into the group's space with a new id. The hotkey (⌘⌥C / Ctrl+Alt+C, configurable, active only while signed in) copies the current selection and stores it directly in the default group as history.
